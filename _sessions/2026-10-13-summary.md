# Tome in a modern browser: session summary

13 October 2026, working with Claude Code on `master`. The full conversation is in [2026-10-13-transcript.md](2026-10-13-transcript.md).

## Aim

Make Tome (David Lilley, produced by e-2, technical direction by Thom McIntosh) play in a modern browser without the Cosmo Player 2.0 plugin it was built for, changing as little of the original as possible.

## What was found

- Tome is standard VRML 97 (`#VRML V2.0 utf8`). `tome.html` embedded `vrml/tomemasterall12k.wrl`, which inlines 43 other files: a title, text, nav and audio file for each of the nine rooms, plus the corridor. The other `tomemasterall*.wrl` files are working versions.
- All the files, textures and sounds the main world references are present.
- Only standard nodes are used: geometry, textures, `Text`, lights, interpolators, around 1,650 `ROUTE`s, `TouchSensor`, `ProximitySensor`, `Sound`/`AudioClip` with plain PCM WAVs, and 88 small `javascript:` Script nodes. Nothing depends on Cosmo-specific features.

Three options were considered: a JavaScript VRML player (X_ITE), converting to X3D for X3DOM, or rebuilding in three.js. X_ITE was chosen because it reads the original `.wrl` files as they are.

## What was done

**`tome.html`** was rewritten as a modern HTML page:

- The Cosmo `<embed>` is replaced by `<x3d-canvas>` from X_ITE 16.4.1, loaded from jsDelivr.
- The world loads behind an **ENTER** button, because browsers block audio until the visitor interacts with the page.
- The player is as large as the window allows while keeping the original 533×392 proportions. This keeps the camera-fixed navigation spheres in frame. A full-bleed player would push them off-screen in tall or portrait windows.
- The black page and the `bridav4.gif` back link are kept. The dead Google Analytics (`ga.js`) snippet is removed.

**The nine `vrml/tome*nav01.wrl` files** each got one added line in their `textViewAnim` script, plus a comment in the forward handler:

- **The problem:** each navigation sphere holds an `Anchor` (`url "#viewpointName"`) and a `TouchSensor`, and the script rewrites the Anchor's URL when the sphere is clicked. Cosmo activated both. X_ITE follows the spec more strictly and only activates the innermost sensor, the TouchSensor. So clicks registered but the view never changed.
- **The fix:** after choosing the next view, the script now calls `Browser.loadURL(fViewNow, new MFString())` itself, or `bViewNow` going back. X_ITE handles a `#fragment` passed to `loadURL` by binding the viewpoint of that name. This is standard VRML, so the files would still work in Cosmo. The Anchors are unchanged and the files keep their CRLF line endings.

Nothing else in `vrml/`, `image/` or `audio/` was changed.

## Checks

These were tested in headless Chrome (puppeteer, SwiftShader WebGL) with screenshots:

- the intro title and the scripted fly-in to the house
- the first room
- stepping forward and back through the views with the green and purple spheres, as far as the door view
- clicking the door to play the corridor and "shacklewell no. 8" door sequence and load the second room with its own text and navigation
- the larger player at 1400×800

No script errors were logged and no files were missing; the only 404 was the browser's favicon request. Sound couldn't be heard in a headless test, though no audio errors were logged.

## Status

Changed, not committed. To run it, serve the folder over HTTP (for example `python3 -m http.server`) and open `tome.html`. Opening it as a local file won't work.
